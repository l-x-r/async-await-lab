00 /先理解，再动手

约 3 分钟 · 从 Promise 到 await

async / await 是基于 Promise 的异步写法。它让你用接近从上到下的方式组织异步流程，而不用把每一步都写进 .then() 回调里。代码看起来像同步，等待期间仍然可以把执行权交出去。

A / THE FOUNDATION

Promise：代表一个尚未拿到的结果

比如发起网络请求，结果不会立刻回来。Promise 用一个对象表示这次操作的最终结果；它本身不是结果值，也不代表一个新线程。

pending · 等待中→
fulfilled · 成功值rejected · 失败原因

状态一旦变为成功或失败，就不会再变。用 .then() 处理成功、.catch() 处理失败，也可以在 async 函数中用 await 取得结果。

B / THE FUNCTION

async：给函数一个 Promise 返回值

在函数前加上 async，调用它总会得到一个 Promise。返回普通值时，Promise 会以这个值兑现；返回另一个 Promise 时，会跟随它的最终结果。未捕获的异常会让返回的 Promise 拒绝。

async function answer() {
  return 42;
}
const p = answer(); // p 是 Promise，不是 42
p.then(value => console.log(value)); // 42

async 不会让整个函数延后执行。从调用开始，到遇到第一个 await 之前，函数体仍同步执行。

C / THE PAUSE

await：等结果，再继续当前函数

const value = await operation() 会先调用 operation()，然后暂停当前 async 函数。成功时，value 得到兑现值；失败时，await 在恢复执行时抛出拒绝原因，可以由 try / catch 捕获。

async function read() {
  try {
    const value = await Promise.resolve(42);
    console.log(value); // 42
  } catch (error) {
    console.error(error);
  }
}

即使等待的是普通值或已经兑现的 Promise，await 后面的部分也会异步恢复。await 通常用在 async 函数内，也可用在模块顶层。

D / THE SCHEDULING

为什么外面的代码会先执行？

调用栈记录当前正在执行的函数。await 暂停函数并将执行权交还给调用者；等 Promise 就绪后，后续执行通过微任务调度。

  1. 先执行同步代码async 函数在 await 处暂停，调用者接着往下走。
  2. 再处理已排队的微任务当前任务的同步代码结束后，清空微任务队列，包括已就绪的 await 后续操作。
  3. 之后才有机会执行下一个任务例如到期的计时器回调。它若解决了 Promise，又会使相应的微任务入队。

等待未完成的 Promise 时，后续代码还没准备好；不是每个 await 都会立刻把恢复操作放进微任务队列。

记住这句话

await 暂停的是当前函数，不是整个主线程。并发需要先启动多个异步操作，再等待它们的结果。

02 /同样的任务，不同的等待方式

两项互不依赖的异步任务

先启动再一起等，让等待时间重叠。拖动耗时滑块，看看两种写法差在哪里。

串行 · 做完 A，再做 B

SEQUENTIAL
await taskA();
await taskB();
任务 A
任务 B
等待开始0.0 / 5.0 s

并发 · A、B 同时启动

CONCURRENT
await Promise.all([
  taskA(), taskB()
]);
任务 A
任务 B
等待开始0.0 / 3.0 s

理想计时模型：串行约 5.0s，并发约 3.0s。共享同一时间刻度，不计调度开销。

03 / 你能猜对输出顺序吗？

async function f() {
  console.log('A');
  await 42;
  console.log('B');
}
f();
console.log('C');
提示：42 是普通值，但 await 仍会让出执行权。

几个容易混淆的地方

async 会把代码放到另一个线程吗？

不会。函数在第一次 await 之前仍同步执行。耗时的同步计算依然会阻塞主线程；需要线程并行时可考虑 Web Worker。

await 只能写在 async 函数里吗？

通常写在 async 函数中。JavaScript 模块还支持顶层 await；普通脚本顶层不能直接使用。

Promise.all 遇到失败会怎样？

任意一项拒绝，组合 Promise 就会拒绝，但不会自动取消其他已启动的任务。需要收集全部结果时，可使用 Promise.allSettled。

演示里的队列等于浏览器内部实现吗？

这里使用简化的教学快照：展示与当前示例相关的调用、等待和微任务。计时器回调属于任务；它解决 Promise 后，await 的后续部分才以微任务恢复。
